## 这是什么产品（一句话）

MacHands 是一个 macOS 菜单栏软件，让云端 AI 助手在用户自己的 Mac 上执行命令、读写文件、截屏、控制键鼠。只在官网卖，49 美元买断。我们的服务器 IP 是 `134.199.230.126`。

## 目标

开通一个能用 API 发信的服务，并把我们自己的域名验证成**发件域名**，这样买家收到的许可证邮件来自 `license@<域名>`，不会被扔进垃圾箱。

## 前置条件

- **作业 1 必须已完成**：域名已注册，你能进它的 DNS 管理后台加记录。
- 老板的邮箱。

## 用哪家

**首选 Resend**（`resend.com`）：有免费额度，API 简单，域名验证流程清楚。

**备选 Postmark**（`postmarkapp.com`）：送达率口碑好，但免费额度更小、注册审核更严。

**默认选 Resend**。只有在 Resend 注册不成功时才改用 Postmark，并在回填表里写明原因。

---

## 第一步：注册

1. 用老板的邮箱注册账号。
2. 取消营销邮件的勾选。
3. 邮箱验证信要点开确认。
4. 计划选**免费档**。不要升级到付费档。

## 第二步：添加发件域名

1. 在后台找"域名"入口（**Domains**、Sending Domains、Signing Domains 或类似含义），点新增。
2. 填入作业 1 注册的那个域名（填**根域名**，例如 `example.com`，不要填 `license@example.com`，也不要填 `www.`）。
3. 如果它问"区域 / Region"，选离用户近的默认值即可，不必纠结。
4. 提交后，页面会列出**若干条要你去 DNS 里添加的记录**。典型是：
   - 一条 **TXT** 记录，用于 SPF（值里通常含 `v=spf1 …`）
   - 一条或多条 **TXT** 记录，用于 DKIM（主机名里通常含 `._domainkey`）
   - 可能还有一条 **MX** 记录（用于退信处理）和一条 DMARC 的 TXT 记录

## 第三步：把记录加进 DNS

回到作业 1 的 DNS 管理后台，把上一步列出的记录**原样**加进去。

注意事项：

- **主机名/名称字段的写法各家不同**。有的要求填完整的 `abc._domainkey.example.com`，有的只要填 `abc._domainkey`（自动补上域名）。看你 DNS 后台的提示，**别把域名写两遍**（出现 `example.com.example.com` 就是写错了）。
- **值里的引号**：有的后台要带双引号，有的不要。按后台提示来。
- TXT 值很长时注意**不要被自动换行截断**，复制粘贴要完整。
- **不要动**作业 1 加的那两条 A 记录。
- 加完把**每一条记录的类型、主机名、值**原样抄进回填表——我们要能自己复核。

## 第四步：等待验证

回到发信服务的域名页面，点"验证 / Verify"。

- DNS 记录通常几分钟内生效，偶尔要等到一小时。没通过就等一会儿再点一次。
- 如果 15 分钟后仍不通过，去第三方 DNS 查询页（例如 `https://dnschecker.org/`）查一下你加的那条 TXT 记录是否已经能查到。查不到就是 DNS 那边还没生效或写错了。
- 全部记录显示为**已验证 / Verified** 才算成功。

## 第五步：拿 API key

在后台找 **API Keys** 入口，新建一个 key。

- 名称填 `machands-license`（便于日后辨认）。
- 权限如果可选，选**只能发信**（Sending access）即可，不要给完全权限。
- 生成后**只会显示一次**，务必按下面"安全交接"的办法保存好。

## 第六步：验证成功

1. 域名状态是"已验证"。
2. 在后台记下**免费额度**具体是多少（通常是"每天最多 N 封 / 每月最多 M 封"），写进回填表。
3. 如果后台提供"发一封测试邮件"的功能，用它给老板的邮箱发一封，确认能收到、并且发件人显示的是我们的域名。**不要**用它群发或发给任何其他地址。

## 安全交接

**API key 不要写进回填表、不要贴进聊天记录、不要截图。** 存进老板指定的密码管理器，或直接交给老板本人。回填表里只写"**已通过安全渠道交付**"。
