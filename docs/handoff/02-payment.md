# 阶段一：调研三家，填一张表

候选三家：**Lemon Squeezy**、**Paddle**、**Creem**。

## 目标

不注册、不下单，只把公开信息查清楚，填进下面这张表，交给老板做决定。**你不要替老板选**。

## 怎么查

对每一家，去它的官网找这几处（入口名字各家不同，按含义找）：

- **定价页**：通常叫 Pricing / 定价。看每笔交易抽多少、有没有月费。
- **支持的国家/地区**：通常在帮助中心搜 "supported countries"、"payout countries"、"eligible countries"，或在注册页的国家下拉框里看有没有 China / China mainland。
- **提现方式**：帮助中心搜 "payouts"、"withdraw"、"payout methods"。看能提到哪里（银行账户？PayPal？Wise？），支不支持中国大陆的银行。
- **是不是 merchant of record**：搜 "merchant of record" 或 "MoR"。这个词的意思是"它作为法律上的卖家替你收钱、替你交各国的税"。是 MoR 对我们是好事，省掉自己处理增值税。
- **webhook 能力**：文档里搜 "webhooks"。确认有"订单完成/支付成功"这类事件，并且能配置自定义 URL。
- **测试模式**：搜 "test mode"、"sandbox"。确认上线前能用假订单走通流程。
- **个人 vs 公司**：注册时是否强制要求公司主体、营业执照、税号。

**每一条结论都要附上你是从哪个网址看到的**，写进表里的"出处"列。这些平台的政策经常变，我们要能自己复核。

如果某一项在公开页面上查不到（例如提现到中国大陆的具体规则），**就写"公开页面未说明"**，不要猜，也不要拿别人博客里的说法当官方结论。

# 阶段二：按老板选定的那家开通

## 前置条件

- 老板已明确告诉你选哪一家。
- 作业 1 已完成，你知道 `<域名>` 是什么。
- 老板的邮箱。

下面用 `<渠道>` 指代选定的那家。

## 第一步：注册账号

1. 用老板的邮箱注册。
2. 填写资料时，卖家类型选**个人 / Individual / Sole proprietor**（除非老板另有交代）。
3. **遇到要身份证件、银行卡号、人脸识别、活体检测的步骤，立刻停下交回给人。**（全局禁止事项第 4 条）
4. 邮箱验证信要点开确认。

## 第二步：创建商品

在后台找"商品/产品"入口（Products、Catalog、Items 或类似含义），新建一个：

| 字段 | 填什么 |
|---|---|
| 商品名 | `MacHands` |
| 类型 | **一次性付款**（One-time / Single payment），**不是**订阅 |
| 价格 | **49 USD** |
| 简介 | 见 [05-copy.md](05-copy.md) 里的"商品简介"，中英各一份，按后台语言选用 |
| 交付方式 | 如果问"数字商品怎么交付"，选**不由平台交付 / 我自己发**（我们自己发许可证邮件）。如果它强制要求填一个下载链接或收货说明，填 `https://<域名>/` 并在备注里写"许可证由卖家邮件发送" |

**不要**开启平台自带的许可证/授权码功能（License Keys）——我们自己签发，开了会让买家收到两套东西，反而困惑。

创建完记下**商品 ID**（可能叫 Product ID、Variant ID、Price ID 等；**把你看到的所有 ID 都记下来**，我们不确定要用哪个）。

## 第三步：配置 webhook

在后台找 webhook 入口（Webhooks、Notifications、Developer → Webhooks 或类似含义），新增一个：

- **URL**：`https://<域名>/api/store/webhook/<渠道名>`
  `<渠道名>` 用全小写，三选一：`lemonsqueezy` / `paddle` / `creem`。
  例如选了 Lemon Squeezy 且域名是 `example.com`，就填 `https://example.com/api/store/webhook/lemonsqueezy`
- **订阅哪些事件**：至少要包含"订单完成 / 支付成功"这一类（名字各家不同，常见 `order_created`、`transaction.completed`、`checkout.completed`）。同时**也把"退款 / 撤单"类事件勾上**（refund / dispute / chargeback），我们要能识别。
- 保存后，后台会给出一个 **签名密钥 / Signing secret / Webhook secret**。**记下来，但按下面"安全交接"处理，不要贴进聊天。**

保存时如果平台立刻去 ping 这个 URL 并报错（连不上、404、超时），**这是预期的**——我们的接收服务还没上线。只要它允许你保存就行。如果它**强制要求 ping 通才让保存**，就先把 URL 填成平台自己的示例地址保存，然后在回填表里写明"URL 待改"，交回给人，等我们服务上线后再来改。

## 第四步：拿密钥

在后台找 API 入口（API Keys、Developers、Integrations 或类似含义），生成：

- 一个**测试模式**的 API key
- 一个**正式模式**的 API key

有的平台是一个 key 通过开关切换模式，那就只有一个。把**怎么在测试和正式之间切换**记清楚（是后台开关？还是 key 本身不同？还是 URL 不同？）。

## 第五步：验证成功

1. 后台里能看到那个商品，价格 49 美元，类型是一次性。
2. webhook 条目存在，URL 正确，订阅了支付成功与退款事件。
3. 商品有一个**结账链接**（Checkout URL / Buy link / Share link）。把它复制下来——我们要放到官网的"购买"按钮上。
4. 在**测试模式**下打开那个结账链接，确认页面能正常打开、显示 49 美元、显示商品名 MacHands。**不要真的付款**，看到结账页正常就够了。
